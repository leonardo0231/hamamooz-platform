# گزارش بررسی و نقشه تکمیل پلتفرم هم‌آموز

تاریخ بررسی: ۱۴۰۵/۰۵/۰۴ (2026-07-26)

> به‌روزرسانی: هسته ارزیابی ماهانه ۷۴ شاخصی، Import فارسی ۱۰ستونه، ذخیره
> دیتابیس، API محاسبات و نمایش در پرونده دانش‌آموز پس از این بازبینی اضافه شد.
> بخش‌های A3، تحلیل سه‌ساله، مشاوره و توصیه هوشمند همچنان در نقشه تکمیل هستند.

## جمع‌بندی اجرایی

کد موجود یک MVP قابل‌توجه برای مدیریت آموزشی مدرسه است، اما با محصول نهایی
توصیف‌شده در فایل «School Platform» و خروجی جامع تصویری/اکسل فاصله دارد.
نسخه فعلی دانش‌آموز، ثبت‌نام، ساختار آموزشی، نمره، حضور و غیاب، ارزیابی ماهانه
۷۴ شاخصی، گزارش کارنامه A4 و داشبورد عملیاتی را پوشش می‌دهد؛ ولی پروفایل
۳۶۰ درجه کامل، تحلیل سه‌ساله، مشاوره، فعالیت‌ها و افتخارات، پیشنهادهای هوشمند،
گزارش جامع A3، Word و Excel خروجی هنوز پیاده‌سازی نشده‌اند.

قالب مرجع پیوست ۹۲ ستون دارد و مستقیماً قابل بارگذاری نیست. قالب تمیز v1 با
۱۰ ستون فارسی و نوع `monthly_evaluations` جایگزین آن شده و زیر سقف ۲۰ ستون
فعلی پردازش می‌شود.

## تطبیق فایل اکسل مرجع با سایت

فایل مرجع شامل ۹ حیطه، ۷۴ شاخص، ۱۲ ماه، محاسبه میانگین‌های ۲۰ نمره‌ای، نمره
وزنی، سطح عملکرد، تحلیل دانش‌آموز، بانک راهکار، گزارش و داشبورد است.

فایل مرجع برای تحلیل داخلی Excel مناسب است، ولی قرارداد ورودی پایدار سایت
نیست؛ چون شامل فرمول، داشبورد، شیت‌های کمکی و ستون‌های مشتق‌شده است. قرارداد
ورودی سایت باید فقط داده خام داشته باشد و محاسبه‌ها در Backend انجام شوند.

قالب v1 دارای ۱۰ ستون فارسی است. هر ردیف یک امتیاز شاخص را نگهداری می‌کند:
نسخه، مدرسه، سال، کلاس، شماره دانش‌آموزی، کد ملی، ماه، کد شاخص، امتیاز و
توضیحات. کدهای پایدار شاخص از `EDU_01` تا `PER_07` هستند.

## تغییرات اصلاحی انجام‌شده در این بررسی

1. خطای ترتیب Import در تنظیمات Backend اصلاح شد و Ruff اکنون عبور می‌کند.
2. کاتالوگ Frontend با قرارداد فعلی Backend همگام شد:
   ۱۶۲ Operation ثابت ماند و تعداد Schema از ۱۲۴ به ۱۳۸ رسید.
3. چهار Operation گزارش حضور و غیاب و ۱۵ Schema افزوده/تغییریافته در خروجی
   تولیدشده Frontend اعمال شد.
4. اسکریپت تولید قرارداد Frontend اکنون مسیر صریح
   `HAMAMOOZ_OPENAPI_SOURCE` را برای Checkout مستقل پشتیبانی می‌کند.
5. تست و مستندات شمارش قرارداد Frontend به‌روزرسانی شد.
6. Workflow مستقل Frontend CI برای بازتولید قرارداد، Typecheck، Lint، Test و
   Build اضافه شد.
7. قالب XLSX ورودی v1 با ۷۴ شاخص، Data Validation، راهنما، تعریف شاخص‌ها،
   مقادیر مجاز و نمونه تکمیل‌شده آماده شد.

هیچ Commit، Push، Merge یا تغییری در Pull Requestهای GitHub در این بررسی انجام
نشده است.

## مشکلات انتشار و یکپارچه‌سازی

1. شاخه `main` فقط یک README یک‌خطی دارد و محصول قابل اجرا روی آن نیست.
2. برای شاخه Backend هنوز Pull Request باز وجود ندارد.
3. PR شماره ۲ Frontend به `main` باز است، اما تا ادغام Backend قرارداد و سرویس
   لازم در `main` وجود ندارد.
4. PR شماره ۱ از شاخه مستندات با سیاست فعلی `PR Branch Boundary` سازگار نیست؛
   این Policy فقط شاخه‌های Backend و Frontend را برای `main` مجاز می‌کند.
5. Frontend پیش از اصلاح، در Checkout مستقل قادر به بازتولید قرارداد نبود.
6. Workflow Frontend CI در وضعیت فعلی GitHub وجود نداشت.

ترتیب انتشار پیشنهادی:

1. ساخت PR از `backend/mvp-bootstrap` و عبور کامل Backend CI
2. ادغام Backend در `main`
3. انتقال/ادغام مستندات PR شماره ۱ در مسیر مجاز یا اصلاح آگاهانه Policy
4. Rebase شاخه Frontend روی `main`
5. بازتولید کاتالوگ Frontend از قرارداد ادغام‌شده
6. عبور Frontend CI و سپس ادغام PR شماره ۲
7. ساخت Tag/Release Candidate و اجرای Smoke Test انتها‌به‌انتها

## وضعیت پشتیبانی از قالب ارزیابی ماهانه

### ۱. مدل داده

مدل‌های پیاده‌شده:

- `MonthlyEvaluation`: ثبت‌نام، ماه، نسخه چارچوب، یادداشت، ثبت‌کننده و Import مبدأ
- `MetricScore`: ارزیابی، کد شاخص و امتیاز ۰ تا ۵
- کاتالوگ نسخه‌دار ۹ حیطه و ۷۴ شاخص در لایه Domain

قیود ضروری:

- یکتایی ثبت‌نام + ماه + نسخه چارچوب
- یکتایی ارزیابی + شاخص
- Check Constraint برای ۰ تا ۵
- ذخیره مقدار خالی به‌عنوان Missing، نه صفر
- عدم حذف فیزیکی سوابق تأییدشده
- Revision و Audit برای اصلاحات
- Scope اجباری سازمان/مدرسه در تمام Queryها

### ۲. Import

- اضافه‌شدن `monthly_evaluations` به `ImportType`
- قالب ۱۰ستونه زیر سقف امن فعلی ۲۰ ستون
- خواندن شیت اول با Headerهای فارسی دقیق نسخه 1.0
- اعتبارسنجی نسخه قالب
- تطبیق هم‌زمان مدرسه، سال، کلاس، شماره دانش‌آموزی و کد ملی
- اعتبارسنجی ماه ۱ تا ۱۲ و شاخص ۰ تا ۵
- تشخیص ردیف تکراری داخل فایل و رکورد موجود در پایگاه داده
- سیاست روشن Create/Update/Reject
- مرحله Preview خطاها پیش از Commit
- تأیید کاربر و ذخیره اتمیک
- Idempotency با Checksum و `row_external_id`
- گزارش خطای قابل دانلود با شماره ردیف، ستون، کد خطا و پیام فارسی
- ثبت Audit شامل کاربر، IP، زمان، Checksum، تعداد موفق/ناموفق و نسخه قالب

### ۳. API و Frontend

- endpoint دانلود قالب فعال و نسخه‌دار
- endpoint Upload، Validate/Preview، Confirm و Status
- Progress برای Jobهای بزرگ
- صفحه نگاشت خطاها و امکان دانلود فایل خطا
- جلوگیری از Submit دوباره
- صفحه نمایش ارزیابی ماهانه و تاریخچه Revision
- فیلتر سال، ماه، پایه، کلاس و دانش‌آموز
- کنترل Permission در Backend؛ Role Guard فرانت فقط برای UX

### ۴. محاسبه و تحلیل

- تبدیل امتیاز ۰ تا ۵ به ۰ تا ۲۰ با قاعده مصوب
- محاسبه میانگین هر حیطه
- اعمال وزن‌ها با Versioning
- حداقل Coverage لازم برای نمایش میانگین
- روند ماهانه و سه‌ساله
- تشخیص افت ناگهانی با آستانه و حداقل داده
- نقاط قوت/قابل بهبود با دلیل قابل نمایش
- رتبه با رعایت حداقل اندازه گروه و حریم خصوصی
- Snapshot محاسبات برای تکرارپذیری گزارش تاریخی
- تست Property-based برای مرزها، Missing data و وزن‌ها

### ۵. توصیه هوشمند

- بانک راهکار نسخه‌دار به تفکیک حیطه/شاخص/سطح
- تولید پیشنهاد به‌صورت Draft
- نمایش دلیل و داده مؤثر
- تأیید/ویرایش/رد توسط نقش مجاز
- ذخیره متن نهایی و نسخه الگوریتم
- ممنوعیت انتشار خودکار توصیه حساس برای والد/دانش‌آموز

## معیار پایان کار

کار زمانی کامل تلقی شود که:

- هر Requirement به مدل/API/UI/Test/Output قابل ردیابی باشد.
- فایل v1 بدون ویرایش سرستون در سایت Validate، Preview، Confirm و ذخیره شود.
- داده Importشده در پروفایل ۳۶۰ و داشبوردها دیده شود.
- گزارش A3/PDF و Excel از Snapshot یکسان تولید شوند.
