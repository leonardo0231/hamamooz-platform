# تصمیم‌های معماری

## ADR-001: Django + DRF

وضعیت: پذیرفته‌شده

دلیل: CRUD و Relation زیاد، Admin، Permission، ORM و سرعت توسعه برای سامانه مدرسه. DRF 3.16 با Django 5.2 LTS استفاده شده است.

## ADR-002: Modular Monolith به‌جای Microservice

وضعیت: پذیرفته‌شده

دلیل: ۱۳ شعبه/۴ هزار دانش‌آموز نیازمند پیچیدگی شبکه و Consistency توزیع‌شده نیست. تراکنش ثبت‌نام/نمره ساده و مطمئن باقی می‌ماند. مرز ماژول‌ها امکان Extract آینده را حفظ می‌کند.

## ADR-003: Shared database با Scope صریح

وضعیت: پذیرفته‌شده

دلیل: یک مجموعه با ۱۳ شعبه نیاز به گزارش مشترک دارد. `organization_id` و `school_id` در مسیر داده و RoleAssignment استفاده می‌شوند. Tenant isolation در Query و Object کنترل می‌شود.

## ADR-004: Enrollment سالانه

وضعیت: پذیرفته‌شده

Student به Class متصل نمی‌شود. Enrollment رابط Student + School + AcademicYear + GradeLevel + ClassSection است و انتقال را بدون از دست‌دادن سابقه ممکن می‌کند.

## ADR-005: Decimal و Policy نسخه‌دار

وضعیت: پذیرفته‌شده

Float برای نمره رسمی مناسب نیست. تمام محاسبات Decimal هستند و Rounding فقط در نتیجه انجام می‌شود. Policy خاص‌ترین Scope را انتخاب می‌کند و نسخه روی Result/Report ثبت می‌شود.

## ADR-006: Workflow در Assessment

وضعیت: پذیرفته‌شده

قفل در سطح Assessment است، چون تأیید معاون معمولاً یک دفتر نمره/آزمون کامل را پوشش می‌دهد. اصلاح استثنایی Score قفل‌شده Assessment را Unlock نمی‌کند و Audit مستقل دارد.

## ADR-007: Import تمام یا هیچ

وضعیت: پذیرفته‌شده

در MVP قالب ثابت است. کل فایل قبل از Write اعتبارسنجی می‌شود؛ وجود یک خطا کل Job را Fail می‌کند. این رفتار از دیتای نیمه‌واردشده و Reconciliation دستی جلوگیری می‌کند.

## ADR-008: PDF Snapshot

وضعیت: پذیرفته‌شده

فایل به‌تنهایی برای Audit کافی نیست. JSON داده، نسخه فرمول و PDF کنار هم آرشیو می‌شوند. Preview آرشیو نمی‌سازد؛ Generate رسمی فقط پس از Lock کامل همه ارزیابی‌های درس‌های فعال آرشیو می‌سازد.

## ADR-009: UUID عمومی

وضعیت: پذیرفته‌شده

UUID حدس‌زدن شناسه‌ها را سخت‌تر و ادغام/تفکیک سرویس آینده را آسان‌تر می‌کند؛ امنیت همچنان به Permission وابسته است و UUID جایگزین Authorization نیست.

## ADR-010: ML/AI خارج MVP

وضعیت: پذیرفته‌شده

در MVP داده تاریخی و فرآیند تأیید انسانی هنوز تثبیت نشده است. تحلیل و AI زودهنگام ریسک نتیجه گمراه‌کننده دارد. نتایج نسخه‌دار و Snapshotها زیرساخت داده لازم برای مرحله بعد را فراهم می‌کنند.
