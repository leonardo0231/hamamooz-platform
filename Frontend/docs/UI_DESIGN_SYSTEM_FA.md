# جهت طراحی رابط کاربری هم‌آموز

## تصمیم معماری

برای بازطراحی فعلی، فریم‌ورک Frontend عوض نمی‌شود. کد فعلی یک TypeScript SPA ماژولار با router، API client، component primitives، role-aware navigation و تست‌های مستقل دارد. مهاجرت کامل به React/Next.js در این مرحله هزینه و ریسک بالایی ایجاد می‌کند، بدون اینکه برای رسیدن به ظاهر مرجع یا نیاز فعلی محصول الزام فنی داشته باشد.

اگر در آینده پیچیدگی state تعاملی، reuse کامپوننت‌ها یا نیازهای editor-like از ظرفیت ساختار فعلی عبور کرد، React + TypeScript به‌صورت SPA گزینه بعدی است. Next.js فقط در صورت نیاز واقعی به SSR/SEO یا server-side frontend runtime توجیه دارد.

## زبان بصری

جهت نهایی ترکیب دو مرجع اصلی است:

- ساختار اطلاعاتی «Analytical»: سایدبار ثابت سمت راست، topbar کم‌ارتفاع، KPIهای واضح، نمودارها و جداول تصمیم‌محور، تمرکز روی هشدار و پیگیری.
- حس «Warm»: زمینه گرم و روشن، سطوح سفید، گوشه‌های نرم، سایه‌های بسیار کم، رنگ‌های وضعیت آرام‌تر و فاصله‌گذاری انسانی‌تر.

نتیجه باید حرفه‌ای و مدیریتی باشد؛ نه یک داشبورد تزئینی. رنگ فقط برای hierarchy، وضعیت و action استفاده می‌شود.

## قواعد ثابت

1. RTL از ریشه سند حفظ می‌شود و هیچ صفحه‌ای نباید با hackهای LTR چیدمان اصلی را بسازد.
2. سایدبار دسکتاپ سمت راست است و در موبایل به drawer قابل دسترس تبدیل می‌شود.
3. navigation سطح اول بر اساس workspace است، نه فهرست بلند endpointها یا resourceها.
4. هر نقش فقط workspaceها و داده‌هایی را می‌بیند که Backend مجاز کرده است؛ مخفی‌سازی UI مرز امنیتی نیست.
5. داشبورد باید ابتدا «چه چیزی نیازمند توجه است؟» را پاسخ دهد؛ KPI و نمودار بعد از آن می‌آیند.
6. success/warning/danger فقط معنای وضعیت دارند و نباید برای تزئین استفاده شوند.
7. cardها radius و shadow یکسان دارند؛ nesting کارت داخل کارت تا جای ممکن محدود می‌شود.
8. فرم‌ها و جدول‌ها باید loading/error/empty state مشخص و focus قابل مشاهده داشته باشند.
9. motion کوتاه و اختیاری است و `prefers-reduced-motion` رعایت می‌شود.
10. تغییرات بصری نباید API contract، tenant scope یا permission semantics را دور بزنند.

## توکن‌های اصلی

پیاده‌سازی فعلی در `src/styles/design-refresh.css` قرار دارد و بعد از `app.css` و `product.css` بارگذاری می‌شود تا migration بصری تدریجی و کم‌ریسک بماند.

- canvas: خاکستری بسیار روشن با گرمای کم
- surface: سفید
- navigation: navy عمیق
- primary action: blue/cyan
- success: teal/green
- warning: amber
- danger: coral/red
- card radius: 18px
- control radius: 10–12px

## معیار پذیرش صفحه

هر صفحه جدید یا بازطراحی‌شده باید در desktop، tablet و mobile بررسی شود؛ keyboard navigation، focus، empty/error/loading state و RTL باید قابل استفاده باشند. اگر صفحه فقط زیباتر شده اما تصمیم کاربر را سریع‌تر نکرده، بازطراحی کامل محسوب نمی‌شود.
