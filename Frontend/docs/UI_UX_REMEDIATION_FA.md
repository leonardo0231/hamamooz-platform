# ممیزی UI/UX و قواعد طراحی

## هدف و شواهد

شش تصویر مرجع به‌عنوان شواهد طراحی بررسی شدند. تصاویر ۱ تا ۴ منبع اصلی ساختار و رنگ‌اند؛ تصاویر ۵ و ۶ فقط برای چگالی اطلاعات و الگوی مقایسه داده استفاده شدند. هدف، کپی‌کردن یک فریم منفرد نبود؛ یک سیستم قابل توسعه ساخته شد که همه صفحات محصول در آن هم‌خانواده باشند.

## معماری اطلاعات

| سطح | مقصدهای اصلی |
|---|---|
| پایش روزانه | داشبورد، هشدارها، پیشنهادهای هوشمند |
| دانش‌آموز | فهرست دانش‌آموزان، پرونده ۳۶۰، حضور و غیاب، عملکرد آموزشی |
| عملیات | اقدامات و پیگیری‌ها، گزارش‌ها، ورود اطلاعات |
| مدیریت | کاربران، نقش‌ها، تنظیمات و منابع پایه |

ناوبری راست ثابت است، active state یک بلوک بنفش واضح دارد و عنوان/جست‌وجو/انتخاب سال تحصیلی در header مشترک قرار گرفته‌اند.

## سیستم طراحی

- رنگ پایه: سرمه‌ای تیره برای navigation، بنفش برای focus و انتخاب، سبز/کهربایی/قرمز برای semantic state.
- spacing بر شبکه ۴ پیکسل و radius کارت‌ها ۱۴ تا ۲۴ پیکسل.
- کارت‌ها مرز خاکستری روشن، سایه کم و padding ثابت دارند.
- عددهای KPI با `font-variant-numeric: tabular-nums` خواناتر شده‌اند.
- iconها SVG داخلی‌اند تا وزن بصری و رنگ در تمام صفحات یکسان باشد.

## قوانین responsive

| عرض | رفتار |
|---|---|
| بیشتر از 1180px | سایدبار ثابت، KPI چهارستونه و پنل‌های تحلیلی کنار هم |
| 760px تا 1180px | grid دو ستونه، header فشرده و نمودارها تمام‌عرض |
| کمتر از 760px | drawer سایدبار، کارت تک‌ستونه، actionهای stack و جدول scroll افقی |

هیچ داده مهمی در mobile حذف نمی‌شود؛ اولویت با reorder و collapse است.

## انتخاب نمودار و جدول

- line chart فقط برای روند زمانی استفاده شده و محور/label کوتاه دارد.
- bar chart برای مقایسه پایه‌هاست؛ baseline صفر و مقدار روی ستون حفظ می‌شود.
- donut برای نسبت حضور امروز استفاده می‌شود؛ درصد در مرکز و legend متنی کنار آن است.
- جدول دانش‌آموزان header ثابت بصری، ردیف clickable، badge وضعیت و action مشخص دارد. در عرض کم با overflow افقی محافظت می‌شود.

## state matrix

| State | نمایش | اقدام کاربر |
|---|---|---|
| Loading | skeleton هم‌شکل محتوا | انتظار بدون جابه‌جایی شدید layout |
| Empty | عنوان، توضیح و action مرتبط | تغییر فیلتر یا ایجاد داده |
| Error | پیام فارسی و retry | تلاش دوباره |
| Partial | cardهای سالم + پیام بخش ناموفق | ادامه کار و retry همان بخش |
| Success | محتوای اصلی و timestamp/label | مشاهده جزئیات یا اقدام بعدی |

## ریسک‌های باقی‌مانده

1. داده واقعی Backend ممکن است shape متفاوتی از fixtureهای demo داشته باشد؛ contract-fixture test باید گسترش یابد.
2. تأیید pixel-level و keyboard journey به preview مرورگر واقعی نیاز دارد.
3. صفحات عمومی مدیریت فعلاً از template مشترک استفاده می‌کنند و می‌توانند در iteration بعدی برای workflowهای اختصاصی غنی‌تر شوند.
