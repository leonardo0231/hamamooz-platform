# گزارش اصلاح UI/UX فرانت‌اند هم‌آموز

## دامنه کار

این اصلاحات روی سورس ارسالی Frontend و بدون تغییر قرارداد Backend انجام شده‌اند. هدف اصلی، حذف نمایش‌های فنی و خام از مسیر کاربران مدرسه و تبدیل Generic CRUD به رابطی خواناتر و قابل‌استفاده‌تر بوده است.

## تغییرات اعمال‌شده

### ۱. حذف نمایش مستقیم JSON

- پنجره نمایش جزئیات و نتیجه عملیات از `<pre>` و `JSON.stringify` به نمایش ساختاریافته تبدیل شد.
- Objectها به کارت‌های عنوان/مقدار، Arrayها به جدول یا Chip و ساختارهای تو در تو به بخش‌های خوانا تبدیل می‌شوند.
- شناسه‌ها و URLهای فنی در بخش جمع‌شونده «جزئیات فنی» قرار می‌گیرند.

فایل‌های اصلی:

- `src/components/data-view.ts`
- `src/pages/resource.ts`
- `src/utils/dom.ts`

### ۲. حذف ورود JSON از فرم‌های کاربران

- فیلدهای Object به Fieldsetهای ساختاریافته تبدیل شدند.
- Arrayهای Object به ردیف‌های قابل افزودن/حذف تبدیل شدند.
- Arrayهای Enum به Multi-select و فایل‌های چندگانه به File input مناسب تبدیل شدند.
- خطای «JSON نامعتبر» و Textarea خام JSON از تجربه کاربر حذف شد.

فایل اصلی:

- `src/components/schema-form.ts`

### ۳. انتخاب Relation با نام به‌جای UUID

برای موجودیت‌هایی مانند مدرسه، مجموعه، سال تحصیلی، نوبت، کلاس، دانش‌آموز، ثبت‌نام، ولی، دبیر، ارزیابی، درس و سیاست حضور:

- گزینه‌ها از Endpoint رسمی همان موجودیت دریافت می‌شوند.
- کاربر با نام یا کد جست‌وجو می‌کند.
- مقدار فنی UUID همچنان در Payload رسمی API ارسال می‌شود، اما در UI از کاربر درخواست نمی‌شود.
- انتخاب هنگام جست‌وجوی مجدد حفظ می‌شود.

### ۴. عملیات هر ردیف

- مجموعه آیکون‌های بدون متن و کنترل‌های مبهم با دکمه واضح «عملیات» جایگزین شد.
- عملیات در Dialog دارای عنوان، توضیح و آیکون معنایی نمایش داده می‌شوند.
- عملیات مشاهده جزئیات، ویرایش و حذف همچنان مستقیم و قابل‌تشخیص باقی مانده‌اند.

### ۵. یکپارچه‌سازی برچسب‌ها

- نام فیلدها، وضعیت‌ها، Roleها، نوع Import و نوع گزارش در یک لایه مرکزی فارسی‌سازی شدند.
- Dashboard، جدول‌های عمومی، فرم‌ها و جزئیات از همین Presentation Layer استفاده می‌کنند.
- رخدادهای Audit ناشناخته به‌جای عبارت فنی خام، عنوان فارسی قابل‌فهم دریافت می‌کنند.

فایل اصلی:

- `src/ui/presentation.ts`

### ۶. اصلاح معماری ناوبری

- «نمای کلی» به ابتدای منو منتقل شد.
- عنوان‌های مبهم با عنوان‌های دامنه‌ای جایگزین شدند:
  - آموزش و ارزیابی
  - حضور و غیاب
  - کلاس‌ها و برنامه درسی
  - گزارش‌ها و کارنامه‌ها

### ۷. محدودسازی اطلاعات فنی

- Base URL، تعداد Schema و اطلاعات Integration فقط برای مدیر کل سامانه نمایش داده می‌شوند.
- این اطلاعات داخل بخش جمع‌شونده قرار گرفته‌اند و در مسیر کاربران مدرسه ظاهر نمی‌شوند.

### ۸. Build قابل‌حمل

ZIP ورودی شامل `node_modules` ویندوزی بود و Binary مربوط به esbuild در لینوکس قابل اجرا نبود. Build script به‌گونه‌ای اصلاح شد که:

1. در حالت عادی از esbuild استفاده کند.
2. اگر Binary پلتفرم در دسترس نبود، از خروجی استاندارد TypeScript ES Modules استفاده کند.

ماژول SheetJS مورد استفاده برای Preview فایل Excel داخل `src/vendor/` نگهداری می‌شود تا Browser import به Bare module یا CDN وابسته نباشد. مجوز آن نیز همراه سورس قرار دارد.

## محدودیت بررسی

Backend اجرایی و حساب آزمایشی همراه ZIP ارائه نشده بود؛ بنابراین Flowهای متصل به داده واقعی در مرورگر E2E اجرا نشدند. Contract، Build و تست‌های موجود و افزوده‌شده با موفقیت بررسی شده‌اند، اما تست نهایی نقش‌به‌نقش با داده Production باید در محیط Staging انجام شود.

## پیشنهاد ادامه

مرحله بعدی محصول باید ساخت صفحات اختصاصی دامنه‌ای برای Gradebook، Attendance Roster، پروفایل ۳۶۰ درجه دانش‌آموز و Case Management هشدارها باشد. اصلاحات این بسته زیرساخت لازم را فراهم می‌کنند، اما برای ایجاد آن صفحات به Aggregate APIها و Roleهای تکمیلی Backend نیز نیاز است.
